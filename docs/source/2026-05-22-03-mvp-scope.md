# MVP scope

## Cel MVP

Celem MVP jest sprawdzenie, czy podstawowy loop gry jest przyjemny, czy gracze czują wybór i czy przerywniki rzeczywiście budują atmosferę zamiast tylko spowalniać rozgrywkę.

MVP nie musi mieć pełnego multiplayera, kont użytkowników, płatności ani edytora kart.

## MVP - funkcje obowiązkowe

- stworzenie sesji gry,
- dodanie 2-8 graczy,
- pseudonimy graczy,
- wybór poziomu startowego pikantności,
- wybór maksymalnego poziomu pikantności,
- wybór tempa gry,
- podstawowe potwierdzenie 18+,
- rozdanie kart na rękę,
- ekran ręki gracza,
- ekran aktualnej tury,
- zagrywanie kart,
- dobieranie kart,
- podstawowy rzut kością,
- prosta punktacja,
- możliwość odmowy zadania,
- ekran wyników,
- zakończenie gry.

## MVP - typy kart

MVP powinno zawierać minimum:

- pytanie,
- wyzwanie,
- przerywnik,
- kontra,
- zmiana osoby / przekierowanie,
- karta grupowa.

## MVP - tryb działania

Najprostszy wariant MVP:

- jeden telefon,
- lokalny stan gry,
- gracze przekazują telefon,
- brak kont użytkowników,
- brak backendu albo tylko mock API,
- talia zaszyta lokalnie jako JSON/TS fixture.

Drugi etap MVP może dodać backend i multiplayer.

## MVP - poza zakresem

Na start nie robić:

- publicznych profili,
- publicznego UGC,
- publicznego katalogu talii użytkowników,
- matchmakingu,
- czatu,
- płatności,
- natywnej aplikacji iOS,
- Bluetooth multiplayera,
- pełnego edytora kart,
- zaawansowanych animacji.

## Etapy po MVP

### Etap 2

- edytor prywatnych kart,
- zapisywanie talii lokalnie w IndexedDB,
- pobieranie talii offline,
- lepsze ustawienia granic.

### Etap 3

- backend Java/Spring Boot,
- pokoje gry,
- kod pokoju lub link zaproszenia,
- WebSocket,
- synchronizacja stanu gry.

### Etap 4

- konta opcjonalne,
- płatne talie,
- integracja płatności po weryfikacji regulaminów dla adult content,
- łagodniejsza wersja pod App Store, jeśli kiedyś będzie potrzebna.
